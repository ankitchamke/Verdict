Build Phase 2 of Verdict.

Phase 1 is already implemented and working. Do NOT rebuild the project from scratch and do NOT change the existing visual direction unnecessarily.

GOAL:
Build the complete Verdict analysis experience and results screen using MOCK DATA for now.

We are intentionally NOT integrating Clerk or an AI API in this phase. The purpose is to make the core product experience and UI polished before connecting the real backend.

CORE FLOW:

Landing page:
User enters an idea → clicks "Get my verdict" → show an analysis/loading state → reveal the verdict results page.

1. ANALYSIS LOADING EXPERIENCE

When the user submits an idea:

* Capture the textarea value.
* If the input is empty, show a polished validation message.
* Transition into a dedicated loading state.
* Make it feel like Verdict is actually interrogating/analyzing the idea.

Use copy such as:

"Interrogating your idea..."
"Looking for the weak spots..."
"Checking who actually needs this..."
"Finding the competition..."

Use subtle animations/progress effects.

The loading state should feel fun and premium rather than like a generic spinner.

After a short simulated delay, show the results using mock data.

IMPORTANT:
Clearly structure the code so the simulated delay/mock analysis can later be replaced by the real AI API call without rebuilding the UI.

2. RESULTS SCREEN

Create a visually impressive verdict results page.

At the top show:

"Your Verdict"

Then display a large, visually dominant score such as:

7.8 / 10

Add a short one-line explanation underneath.

The score should be the visual centerpiece.

Consider using a tasteful animated circular/ring score visualization or another premium score treatment.

Do NOT make the screen look like a generic dashboard.

3. EXACTLY FIVE VERDICT SECTIONS

The results must contain exactly these five sections:

1. Score /10

* Score
* One-line reasoning

2. Who's it for

* A specific target user
* Never use "everyone"

3. Biggest risk

* The single biggest risk that could kill the idea

4. Closest competitors

* 2–3 competitors

5. What would make it 10x better

* One sharp, actionable suggestion

Use polished cards/sections with strong hierarchy.

Do not add extra verdict categories such as:

* Market size
* Revenue potential
* Marketing strategy
* Tech stack
* Business model
  etc.

Those can potentially be added later, but the core Verdict must stay exactly five sections.

4. IDEA CONTEXT

Show the original idea somewhere on the results page in a subtle, elegant way so the user remembers what was analyzed.

Example:

YOUR IDEA
"An AI tool that helps students choose projects..."

Do not let this overpower the actual verdict.

5. ACTIONS

Add polished actions such as:

"Analyze another idea"

This should return the user to the landing/input experience.

Also include a subtle placeholder/button for a future sharing feature, but DO NOT implement actual sharing yet.

6. ANIMATIONS

Make the result reveal feel satisfying.

For example:

* Score animates/counts upward
* Score visualization animates
* Cards reveal sequentially
* Subtle hover interactions
* Smooth page transitions

Keep animations tasteful and fast.

7. FOOTER

Add a polished footer to the application.

Include:

"Built by Ankit Chamke"

Link the GitHub icon/button to:
https://github.com/ankitchamke

Link the LinkedIn icon/button to:
https://www.linkedin.com/in/ankitchamke/

Use appropriate recognizable icons if the current project already has an icon library. Otherwise use a lightweight appropriate solution rather than adding a large unnecessary dependency.

Links should:

* Open in a new tab
* Use safe external-link attributes
* Have accessible labels/tooltips

The footer should feel like part of the product design, not an afterthought.

8. RESPONSIVENESS

Make the results page excellent on:

* Desktop
* Tablet
* Mobile

On mobile, ensure:

* Score remains visually prominent
* Cards don't feel cramped
* Text remains readable
* Buttons are easy to tap
* Footer adapts cleanly

9. CODE QUALITY

Keep the implementation simple and understandable.

Do NOT add:

* Clerk
* Database
* AI API
* Backend
* Authentication
* Real sharing
* Roast Mode
* Compare Ideas

Those belong to later phases.

Use mock verdict data for now.

IMPORTANT:
Keep the mock verdict data in a clearly separated location/object so that Phase 3 can replace it with real AI-generated structured JSON.

The final experience should feel like:

Landing → Enter idea → Interrogating your idea → Big score reveal → Five sharp insights → Analyze another idea

Make the result screen polished enough to be the centerpiece of a buildathon demo.
